## Загальний флоу

Основний агент **не реалізує сторі сам** — він делегує реалізацію кожної сторі окремому сабагенту через `Agent` tool. Сторі виконуються **послідовно, по одній за раз** (не паралельно): наступна сторі стартує лише після того, як попередня повністю пройшла всі кроки нижче, включно з комітом.

Перед запуском першої сторі позначити її статус у таблиці вище як 🔄 в роботі.

---

## Кроки виконання однієї сторі

Сабагент, якому делеговано сторі, проходить рівно ці кроки по порядку:

1. **Реалізувати вимоги сторі** — усі зміни по файлах, описані в розділі "Зміни по файлах" відповідного `story-XXX.md`.
2. **Відмітити виконане в самій сторі** — проставити `[x]` у чеклисті "Definition of done" цього `story-XXX.md` для кожного виконаного пункту.
3. **Перевірити повноту** — звірити, що всі пункти DoD зі story-файлу дійсно виконані (жоден пункт не пропущено, жоден не позначений завчасно).
4. **Запустити тести й білд** — `make rebuild` (компіляція), `make test` (юніт-тести), і `make connected-test`, якщо у сторі є інструментальні тести. Усе має бути зелене перед переходом далі.
5. **Запустити ревью** — командою `/code-review` по поточному дифу.
   - Якщо ревьювер має зауваження — повернути їх на виправлення (повторити з кроку 1 для зауважених місць), потім знову кроки 3–5.
   - Якщо зауважень немає — перейти до кроку 6.
6. **Зафіксувати завершення**:
   - Позначити сторі як ✅ готово в таблиці на початку цього файлу (`execution-plan.md`).
   - Додати запис у `design-change-log.md` (у цій же папці; створити файл при першому записі, якщо його ще немає) — які проблеми виникли під час реалізації, як їх вирішили, які зміни внесені. Формат запису — див. нижче.
7. **Закомітити** — один коміт на всю сторі, з описовим повідомленням (що зроблено і навіщо, без згадки внутрішніх ітерацій виправлення).
8. **Перейти до наступної сторі** зі списку вище, повторюючи кроки 1–8, поки всі чотири сторі не матимуть статус ✅ готово.

## Формат запису в `design-change-log.md`

Файл ведеться в хронологічному порядку, один розділ на сторі:

```markdown
## Story XXX — <назва>

**Дата:** <дата завершення>

### Проблеми під час реалізації
- <опис проблеми, якщо була; або "без відхилень від плану">

### Рішення
- <як вирішено>

### Зміни
- <короткий підсумок фактичних змін — файли/поведінка, якщо відрізняються від того, що описано в story-файлі>
```

Якщо реалізація повністю збіглася з планом у story-файлі без ускладнень — розділи "Проблеми" і "Рішення" пишуться коротко ("без відхилень"), а "Зміни" все одно фіксується для історії.
