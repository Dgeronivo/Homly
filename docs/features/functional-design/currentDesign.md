# Поточний функціональний дизайн Homly

*Дата створення: 2026-07-19*

Опис того, що користувач бачить і може робити в застосунку сьогодні. Технічну механіку (Room, ViewModel, use cases) навмисно опущено — фокус на UI, діях і інформації.

Застосунок — сімейний планувальник: Аутентифікація → Головна → 3 фічі (Календар, Список покупок, Список справ).

---

## 1. Аутентифікація

### 1.1 Екран входу (Sign In)
- Заголовок "Sign In", поле **Login**, поле **Password** (приховане, з іконкою маски пароля).
- Під кожним полем — постійна підказка з правилами: логін — тільки латиниця та цифри, мін. 3 символи; пароль — мін. 4 символи, латиниця/цифри/спецсимволи. Підказка замінюється на текст помилки при невалідному вводі.
- Кнопка **Login** активна, лише коли обидва поля валідні; під час запиту замість кнопок показується спінер (поля блокуються).
- Загальна помилка автентифікації (напр. "невірний логін/пароль") показується окремим рядком під полями.
- Кнопка **Register** — перехід на екран реєстрації.
- Enter/Done на клавіатурі при валідній формі теж запускає логін.
- Успішний вхід → перехід на Головну (стек аутентифікації очищується).

### 1.2 Екран реєстрації (Create Account)
- Той самий макет, що й Sign In: **Login**, **Password**, ті самі правила валідації та підказки.
- Кнопка **Register**, посилання **Login** для повернення на екран входу.
- Успішна реєстрація одразу логінить і веде на Головну.

**Що користувач НЕ може:** відновити пароль, побачити список правил перед тим як почати вводити (з'являються лише як statically visible hint, не помилка), вийти з реєстрації інакше ніж кнопкою "Login" (немає back-стрілки в topbar — лише системний back).

---

## 2. Головна сторінка (Home)

Найпростіший екран застосунку:
- Привітання "Hello {login}".
- Три кнопки-навігатори одна під одною: **Shopping list**, **Todo list**, **Calendar**.
- Кнопка **Log out** внизу.

Це суто список посилань по центру екрана — без прев'ю даних (скільки товарів у списку покупок, скільки подій сьогодні, скільки невиконаних завдань), без сімейного контексту, без брендування. Немає AppBar, немає індикації поточного користувача крім тексту привітання.

## 3. Календар

### 3.1 Екран календаря (місяць)
- **Заголовок місяця** (напр. "May 2026") + іконка календаря праворуч — відкриває діалог вибору місяця/року.
- **Сітка місяця**: понеділок-перший, 6 тижнів завжди показано (включно з днями сусідніх місяців — тьмяним кольором). Неділя виділена кольором помилки (червоний текст). Обраний день має кільце-рамку. Дні з подіями мають маленьку крапку під числом.
- Клік на день (лише поточного місяця) — обирає його і показує список подій знизу.
- **Список подій обраного дня** під роздільником:
  - Порожній стан: "No events for this day".
  - Рядок події: назва, час (`HH:mm–HH:mm` або "All day"), кнопка видалення (✕).
  - Клік на рядок (не на ✕) відкриває подію в режимі редагування.
  - Клік на ✕ відкриває діалог підтвердження "Delete this event?" (Delete/Cancel).
- **FAB "+"** внизу праворуч — додати подію на обраний день. Якщо ліміт подій (100/користувача) вичерпано — FAB не веде далі, а показує Snackbar "Event limit reached (max 100 events)".
- **Діалог вибору місяця/року**: степер року (◄ рік ►) + сітка з 12 місяців (скорочені назви, локалізовані), кнопки OK/Cancel.
- Екран автоматично оновлює дані при поверненні з екрана додавання/редагування (напр. після збереження чи видалення).

### 3.2 Екран додавання/редагування події
- AppBar: заголовок "Add event" / "Edit event", стрілка назад (‹) — скасовує.
- Поле **Title** з інлайн-помилкою.
- Кнопка **Date: {d MMM yyyy}** — відкриває системний DatePicker (OK/Cancel). При створенні дата попередньо заповнена обраним у календарі днем (AC-13).
- Перемикач **All day** (Switch).
- Якщо не "All day": кнопки **Start: HH:mm** та **End: HH:mm**, кожна відкриває TimePicker (24-год формат). Помилка часу (напр. "End time must be after start time") показується під ними.
- Загальна помилка форми — окремим рядком нижче.
- Кнопка **Save** (на всю ширину), вимикається під час збереження.
- Після успішного збереження — автоматичний перехід назад на календар.

**Обмеження:** назва події — максимум 100 символів, не може бути порожньою; для не-all-day подій кінець має бути строго пізніше початку.

## 4. Список покупок (Shopping list)

- AppBar: "Shopping list", стрілка назад.
- **Рядок додавання**: текстове поле "Add item" + кнопка **Add**. Кнопка активна лише коли текст не порожній і ліміт (50 позицій) не вичерпано. При вичерпанні ліміту поле блокується і показує "List is full (max 50 items)". Клавіатурне Done теж додає товар.
- **Перемикач сортування**: два чіпи — **Date** (за замовчуванням, найновіші перші) і **A–Z** (алфавітний).
- **Список товарів**:
  - Порожній стан: "Your shopping list is empty".
  - Кожен рядок: чекбокс (куплено/ні), назва товару (закреслена, якщо куплено), кнопка видалення (✕).
  - Клік на назву товару (не в режимі checkbox/delete) переводить рядок в inline-редагування тексту; Done/onDone зберігає.
  - Немає кнопки скасування редагування — тільки збереження через Done.
- Видалення миттєве, без підтвердження (на відміну від Календаря).

**Обмеження:** максимум 50 товарів, назва до 100 символів.

---

## 5. Список справ (Todo list)

Структурно ідентичний Списку покупок, без сортування:
- AppBar: "Todo list", стрілка назад.
- Рядок додавання: поле "Add item" + кнопка **Add**, той самий ліміт-стан (50 елементів, повідомлення "List is full (max 50 items)").
- Список: чекбокс (виконано/ні), назва (закреслена коли виконано), inline-редагування по кліку на текст, кнопка видалення (✕, без підтвердження).
- Порожній стан: "Your todo list is empty".
- Немає сортування чи фільтрації (наприклад, приховати виконані).

**Обмеження:** максимум 50 елементів, заголовок до 100 символів.

---

## 6. Наскрізні патерни в поточному дизайні

| Патерн | Де застосовано |
|---|---|
| Inline-редагування по кліку на текст (без окремої кнопки Edit) | Shopping, Todo |
| Ліміт елементів з попереджувальним текстом у полі | Shopping (50), Todo (50), Calendar (100, через Snackbar) |
| Підтвердження видалення діалогом | тільки Calendar |
| Миттєве видалення без підтвердження | Shopping, Todo |
| Порожній стан — просто текст по центру | Shopping, Todo, Calendar (день без подій) |
| Немає ілюстрацій/іконок у порожніх станах | усюди |
| Немає pull-to-refresh, немає swipe-дій (swipe-to-delete) | усюди |
| Немає пошуку/фільтрації | Shopping, Todo, Calendar |
| Немає групування (напр. "куплено" окремо від "ще купити") | Shopping, Todo |
| Немає підтвердження виходу (Log out) | Home |
| Немає індикації "сім'ї" чи інших користувачів попри те, що це "family planning app" | усюди |

## Резюме по екранах

| Фіча | Екрани | Основні дії |
|---|---|---|
| Auth | Sign In, Create Account | ввести логін/пароль, увійти/зареєструватись |
| Home | Home | перейти до фічі, вийти |
| Calendar | Місяць+день, Add/Edit подія, Month/Year picker | обрати день, переглянути/додати/редагувати/видалити подію, перейти на будь-який місяць |
| Shopping | Список | додати, редагувати inline, відмітити куплено, видалити, сортувати |
| Todo | Список | додати, редагувати inline, відмітити виконано, видалити |
