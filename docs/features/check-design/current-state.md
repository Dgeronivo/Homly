# Поточний стан екранів (знімок перед експериментами з дизайном)

*Дата фіксації: 2026-07-19*

Знімок фактичного стану UI застосунку Homly станом на зараз — основа для порівняння з варіантами дизайну, які тестуються в цій папці (`docs/features/check-design`). Базується на [functional-design/currentDesign.md](../functional-design/currentDesign.md) + журналі [functional-design/design-change-log.md](../functional-design/design-change-log.md) (сторі 001, 002, 003, 005 — усі позначені готовими в [execution-plan.md](../functional-design/execution-plan.md)), з точковою звіркою проти коду там, де документація не покривала фактичний стан (Home — за прямою вказівкою власника продукту; Calendar — swipe-навігація, якої немає в жодному story-документі).

Технічну механіку (Room, ViewModel, use cases) навмисно опущено — фокус на UI, формах і розташуванні елементів. Кольорова палітра поза увагою цього документа.

---

## 1. Аутентифікація

### 1.1 Екран входу (Sign In)
- Заголовок "Sign In", поле **Login**, поле **Password**.
- Поле пароля має **trailing-іконку "показати/приховати пароль"** (`👁` / `🙈`) — клік перемикає `PasswordVisualTransformation()` ⇄ звичайний текст (Story 002).
- Під кожним полем — постійна підказка з правилами: логін — тільки латиниця та цифри, мін. 3 символи; пароль — мін. 4 символи, латиниця/цифри/спецсимволи. Підказка замінюється на текст помилки при невалідному вводі.
- Кнопка **Login** активна, лише коли обидва поля валідні; під час запиту замість кнопок показується спінер (поля блокуються).
- Загальна помилка автентифікації показується окремим рядком під полями.
- Кнопка **Register** — перехід на екран реєстрації.
- Enter/Done на клавіатурі при валідній формі теж запускає логін.
- Успішний вхід → перехід на Головну (стек аутентифікації очищується).

### 1.2 Екран реєстрації (Create Account)
- Той самий макет, що й Sign In, включно з іконкою показу/приховання пароля: **Login**, **Password**, ті самі правила валідації та підказки.
- Кнопка **Register**, посилання **Login** для повернення на екран входу.
- Успішна реєстрація одразу логінить і веде на Головну.

**Чого немає:** відновлення пароля, попереднього перегляду правил до початку вводу (лише як statically visible hint), виходу з реєстрації інакше ніж кнопкою "Login".

## 2. Головна сторінка (Home)

*Звірено напряму з кодом (`HomeScreen.kt`, `HomeViewModel.kt`) — тут були незафіксовані зміни.*

Три картки фіч одна під одною по центру екрана, без привітання й без AppBar:

| Картка | Текст (є дані) | Текст (порожньо) |
|---|---|---|
| Shopping list | "{n} items left to buy" | "Shopping list is empty" |
| Todo list | "{n} tasks pending" | "All tasks done" |
| Calendar | "Today: {n} events" | "No events today" |

- Кожна картка (`Card`) — заголовок + рядок-зведення, клікабельна цілком, веде у відповідну фічу.
- Порядок карток: Shopping → Todo → Calendar.
- Зведення (лічильники) оновлюються автоматично при поверненні на Home (`ON_RESUME`).
- Кнопка **Log out** внизу під картками — клік відкриває `AlertDialog` підтвердження ("Log out?" / Log out / Cancel), не виходить миттєво.
- Немає привітання, немає AppBar, немає індикації поточного користувача чи сімейного контексту, немає брендування.

## 3. Календар

### 3.1 Екран календаря (місяць)
- **Заголовок місяця** (напр. "May 2026") зліва.
- Праворуч у заголовку — два елементи поруч:
  - **Кругла кнопка "Сьогодні"** — маленький круглий бейдж з числом поточного дня місяця (не текстова кнопка), клік повертає на поточний місяць і обирає сьогоднішній день.
  - Іконка календаря — відкриває діалог вибору місяця/року.
- **Сітка місяця**: понеділок-перший, 6 тижнів завжди показано (дні сусідніх місяців — тьмяним кольором). Неділя — кольором помилки (червоний текст). Обраний день — кільце-рамка. Дні з подіями — крапка під числом.
- **Свайп-навігація між місяцями**: сітка місяця в `HorizontalPager` — гортання вліво/вправо перемикає на сусідній місяць (як і клік по стрілках/іконці вибору місяця, оновлює заголовок і список подій). Дні з подіями показуються (крапка) лише для поточного завантаженого місяця — сусідні місяці під час свайпу показуються без крапок, доки не стануть поточними.
- Клік на день (лише поточного місяця) — обирає його і показує список подій знизу.
- **Список подій обраного дня** під роздільником:
  - Порожній стан: "No events for this day".
  - Рядок події: назва, час (`HH:mm–HH:mm` або "All day"), кнопка видалення (✕).
  - Клік на рядок (не на ✕) відкриває подію в режимі редагування.
  - Клік на ✕ відкриває діалог підтвердження "Delete this event?" (Delete/Cancel).
- **FAB "+"** внизу праворуч — додати подію на обраний день. При вичерпаному ліміті (100/користувача) — Snackbar "Event limit reached (max 100 events)".
- **Діалог вибору місяця/року**: степер року (◄ рік ►) + сітка з 12 місяців, кнопки OK/Cancel.
- Екран автоматично оновлює дані при поверненні з екрана додавання/редагування.

### 3.2 Екран додавання/редагування події
- AppBar: заголовок "Add event" / "Edit event", стрілка назад (‹) — скасовує.
- Поле **Title** з інлайн-помилкою.
- Кнопка **Date: {d MMM yyyy}** — відкриває системний DatePicker. При створенні дата попередньо заповнена обраним у календарі днем.
- Перемикач **All day** (Switch).
- Якщо не "All day": кнопки **Start: HH:mm** та **End: HH:mm** з TimePicker (24-год). Помилка часу — під ними.
- Загальна помилка форми — окремим рядком нижче.
- Кнопка **Save** (на всю ширину), вимикається під час збереження.
- Після успішного збереження — автоматичний перехід назад на календар.

**Обмеження:** назва події — максимум 100 символів, не порожня; кінець строго пізніше початку (не all-day).

## 4. Список покупок (Shopping list)

- AppBar: "Shopping list", стрілка назад.
- **Рядок додавання**: текстове поле "Add item" + кнопка **Add**. Активна лише коли текст не порожній і ліміт (50 позицій) не вичерпано; при вичерпанні — поле блокується, "List is full (max 50 items)". Done на клавіатурі теж додає товар.
- **Перемикач сортування**: два чіпи — **Date** (за замовчуванням) і **A–Z**.
- **Список товарів**:
  - Порожній стан: "Your shopping list is empty".
  - Рядок: чекбокс (куплено/ні), назва (закреслена якщо куплено), кнопка видалення (✕).
  - Клік на назву — inline-редагування тексту; Done зберігає.
  - Немає кнопки скасування редагування.
- Видалення миттєве, без підтвердження.

**Обмеження:** максимум 50 товарів, назва до 100 символів.

## 5. Список справ (Todo list)

*Звірено проти коду (`TodoListScreen.kt`) — фіча отримала зміни в Story 005 після написання базового `currentDesign.md`.*

- AppBar: "Todo list", стрілка назад.
- Рядок додавання: поле "Add item" + кнопка **Add**, той самий ліміт-стан (50 елементів).
- **Рядок керування списком** (новий, під рядком додавання):
  - Чіп-фільтр **"Active only"** (`FilterChip`) — вимкнений за замовчуванням; увімкнений ховає виконані елементи з відображення (дані в БД не змінюються).
  - Кнопка **"Clear completed"** поруч із чіпом — неактивна, якщо виконаних елементів немає (незалежно від стану фільтра); клік відкриває `AlertDialog` "Delete {n} completed tasks?" (Delete/Cancel); підтвердження видаляє всі виконані одразу.
- Список: чекбокс (виконано/ні), назва (закреслена коли виконано), inline-редагування по кліку на текст, кнопка видалення (✕, без підтвердження).
- Порожній стан: "Your todo list is empty".
- Немає сортування (на відміну від Shopping).

**Обмеження:** максимум 50 елементів, заголовок до 100 символів.

## 6. Наскрізні патерни в поточному дизайні

| Патерн | Де застосовано |
|---|---|
| Inline-редагування по кліку на текст (без окремої кнопки Edit) | Shopping, Todo |
| Ліміт елементів з попереджувальним текстом у полі | Shopping (50), Todo (50), Calendar (100, через Snackbar) |
| Підтвердження дією, що видаляє дані | Calendar (подія), Todo (масове очищення виконаних), Home (Log out) |
| Миттєве видалення без підтвердження (одиночний елемент) | Shopping, Todo |
| Порожній стан — просто текст по центру | Shopping, Todo, Calendar (день без подій) |
| Немає ілюстрацій/іконок у порожніх станах | усюди |
| Немає pull-to-refresh, немає swipe-to-delete окремих елементів | Shopping, Todo |
| Свайп-навігація між сторінками контенту | тільки Calendar (місяці) |
| Фільтрація видимого списку без зміни даних у БД | тільки Todo ("Active only") |
| Сортування | тільки Shopping (Date / A–Z) |
| Зведення стану фічі прямо на Home (лічильники) | Home |
| Немає групування (напр. "куплено" окремо від "ще купити") | Shopping, Todo |
| Немає індикації "сім'ї" чи інших користувачів попри те, що це "family planning app" | усюди |

## Резюме по екранах

| Фіча | Екрани | Основні дії |
|---|---|---|
| Auth | Sign In, Create Account | ввести логін/пароль, показати/приховати пароль, увійти/зареєструватись |
| Home | Home | переглянути зведення 3 фіч, перейти до фічі, вийти (з підтвердженням) |
| Calendar | Місяць+день (зі свайпом між місяцями), Add/Edit подія, Month/Year picker | обрати день, гортати місяці свайпом, перейти на "Сьогодні" одним кліком, переглянути/додати/редагувати/видалити подію |
| Shopping | Список | додати, редагувати inline, відмітити куплено, видалити, сортувати |
| Todo | Список | додати, редагувати inline, відмітити виконано, видалити, фільтрувати "Active only", масово очистити виконані |
